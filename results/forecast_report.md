# Forecast model evaluation

Generated by `scripts/run_forecast_evaluation.py`. Every number below comes from that script; nothing is hand-entered. The test window is included only when the run passes `--include-test`. Model selection never uses test results: stability diagnostics are restricted to folds that end at the validation boundary, and a regression test asserts that adding the test window leaves the dev/validation metrics, flags and selected models unchanged.

## Protocol

- Universe: 14 tickers  -  SPX, TECH, FIN, HLTH, ENRG, STPL, INDU, UTIL, INTL, EMEQ, GOVT, CRED, GOLD, REIT
- Sample: 2019-02-05 to 2026-05-28 (1838 feature dates, 25732 asset-date rows)
- Forecast horizon: 21 trading days
- Cross-validation: purged expanding walk-forward, min train 378 days, purge 21 days, embargo 21 days, step 21 days
- Dev: through 2021-12-31; validation: 2022-01-01 to 2023-12-31; test: from 2024-01-01
- Scored feature dates per split: dev 713, validation 480, test 603
- Test included in this run: **yes**

All features are lagged by one trading day and targets are forward returns/vol, so a training row whose target window overlaps a prediction block is purged. The last `horizon` feature dates before each split boundary are excluded from the scored set because their targets reach into the next split. The shuffled control re-runs the Ridge pipeline with training labels permuted across tickers within each date, averaged over three seeds so that one random coefficient direction cannot masquerade as skill.

## Selection

- Selected return model: **`shrunk_mean`**
- Selected volatility model: **`ewma`**
- Rule: Best model per task is chosen on the validation window only. A candidate must beat the best baseline by at least 0.01 rank IC (returns) or 0.01 QLIKE (volatility), must have positive validation rank IC for returns, and must not be flagged for a large train/validation gap; otherwise the baseline is retained.

| volatility | `ewma` | mae | 0.0419 | 0.0440 |

Return rank IC moved from 0.0613 in validation to 0.0977 in test, and RMSE moved from 0.0564 to 0.0436.

Volatility QLIKE improved (-2.4874 to -2.7941), while absolute error worsened or was mixed (RMSE 0.0531 to 0.0704; MAE 0.0419 to 0.0440). This distinction matters: QLIKE is the selection criterion, but it does not mean the forecast is closer in absolute volatility terms.

`har` has a lower test RMSE than the selected `ewma` (0.0649 versus 0.0704), but the selection rule is fixed on validation QLIKE. The test window is not used to promote it after the fact.

The test result is therefore mixed rather than uniformly better: the forecast ranking/QLIKE objective does not guarantee lower absolute errors, and the advisory evaluation should not be read as if it did.

## Reproduction

```bash
python scripts/fetch_real_data.py                    # refresh ETF prices + FRED DGS3MO
python scripts/run_forecast_evaluation.py            # dev + validation only
python scripts/run_forecast_evaluation.py --include-test  # final report
```

The final run adds the test window without re-selecting anything. Results are reported as-is, and the selected models are the same ones chosen on dev/validation alone.
